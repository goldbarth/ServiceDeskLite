# ServiceDeskLite v1.2.0 — Semantic Search (RAG) & Agent Roster

### Summary

ServiceDeskLite 1.2.0 broadens both the AI assistant and the web UI. The
assistant gains a full read-and-write toolbelt — it can now search existing
tickets, update any ticket via find-then-update, change workflow status, and
assign work to real roster accounts, all through the same guarded command
handlers as the REST API. Alongside it, semantic ticket search (RAG) lands as
an optional pgvector + Voyage capability, and a seeded agent roster replaces
free-text assignees so tickets are owned by concrete accounts across the API,
web UI, and assistant.

### Highlights

- Semantic ticket search (RAG) via pgvector + Voyage embeddings, indexed by a background worker (ADR 0024)
- Agent roster with seeded fictitious accounts; assignees are now real entities, not free text (ADR 0025)
- New assistant tools: `search_tickets`, `change_ticket_status`, `assign_ticket`, and update-any-ticket via find-then-update
- Web: inline edit of ticket fields on the details page (pencil → edit mode)
- Web: comment author chosen from the roster instead of typed free text
- All model-facing text centralized in `*.prompt.cs` partials for easier tuning
- Ticket seeder registered for both persistence providers, keeping InMemory and PostgreSQL in parity

### Demo Notes

#### Suggested demo flow

1. Start application (export `ANTHROPIC_API_KEY` for the assistant; add `Voyage:ApiKey` for RAG)
2. Open the assistant chat and ask it to find tickets by topic (`search_tickets`)
3. Ask it to update an existing ticket without giving an id — it resolves via find-then-update
4. Ask it to change a ticket's status and assign it to a roster member
5. Open the ticket list and verify the changes and the audit trail
6. On the ticket details page, use the pencil to edit fields inline
7. Add a comment and pick the author from the roster dropdown
8. With PostgreSQL + Voyage running, try semantic search for near-duplicate tickets

#### What to pay attention to

- Assistant writes still flow through the same command handlers, validation, and audit trail as REST
- RAG degrades honestly: without Voyage or on InMemory it reports search unavailable, not fake empty results
- Assignees resolve to concrete roster accounts, surfaced consistently in API, UI, and audit events
- Inline edit sends only changed fields, matching the partial-update handler semantics

### Included scope

- Semantic ticket search (embeddings, pgvector cosine search, async indexing worker)
- Agent roster and assignee storage with seeded accounts across both persistence providers
- Assistant tools: `search_tickets`, `change_ticket_status`, `assign_ticket`, find-then-update
- Web: ticket details inline edit, roster-backed comment author
- Refactor: model-facing text moved into `*.prompt.cs` partials

### Known limitations

- Not intended for production use
- Still no real auth — the roster is seeded fictitious accounts, not authenticated identities
- RAG is intentionally minimal: no chunking, hybrid FTS, re-ranking, or vector index tuning
- Semantic search requires PostgreSQL + a Voyage API key; without them the rest of the app is unaffected
