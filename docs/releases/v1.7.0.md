# ServiceDeskLite v1.7.0 - Sonnet 5, Container Fixes & a Recorded Test Pass

### Summary

The first six releases each closed a roadmap milestone; this one closes none.
It is what a manual pass over the finished assistant surface produced, and the shape of it is deliberate: before the frontend redesign opens a wide diff across the web layer, the backend gets a clean tag.
Three things changed.
The model the assistant runs on became a decision instead of the default the first request happened to be written with, and thinking was disabled explicitly rather than inherited.
Two container defects were fixed - one that made `docker compose up` fail to bind on any host already running Postgres, and one that printed a red error line above an otherwise healthy boot.
And the pass itself was written down, including the six defects it found that this release does not fix, because a test plan that records only its passes is worth reading once.

### Highlights

- The assistant runs on `claude-sonnet-5`: near-Opus quality on tool-calling work, the same 1M context window, roughly 40% of the bill, and a visibly faster first SSE delta (ADR 0038)
- Thinking is set explicitly at both call sites. Sonnet 5 enables adaptive thinking when the field is absent, where Opus 4.8 does not, and thinking tokens are drawn from `MaxTokens`, which a six-round tool chain already fills. A test asserts the field on the wire body, because a missing field is not an API error
- `docker compose` host ports are overridable via `DB_PORT` and `API_PORT`, with an `.env.example` naming the collision each default hits. The stack had never once run on a host with a second Postgres: `db` failed to bind, `api` never started behind its `service_healthy` gate, and the whole RAG group of the test plan silently ran against InMemory while looking green
- `libgssapi-krb5-2` is installed in the aspnet runtime stage. Npgsql probes it for Kerberos auth, the base image does not ship it, and the failed probe was the first line a reviewer saw. The stack authenticates by password, so nothing was broken - but suppressing the probe would have hidden the symptom rather than removed the cause
- A manual test plan over all twelve tools, summaries, the dashboard, the sandbox and the worker, tracing every deviation to a file and line, and listing what remains untested rather than leaving blank rows unexplained
- The README describes the current surface instead of the v1.2.0 one, and no longer contradicts its own diagram about where conversation state lives

### Demo Notes

#### Suggested demo flow

1. Run the containerised stack on a host that already has Postgres on 5432 - the case that used to fail silently

   ```bash
   cp .env.example .env   # then set DB_PORT=5433, API_PORT=8081
   docker compose up --build
   ```

   The boot log carries no `libgssapi_krb5` error, and the API answers on the port you chose
2. Point the web client at it and run one assistant conversation

   ```bash
   ApiClient__BaseUrl=http://localhost:8081 dotnet run --project src/ServiceDeskLite.Web
   ```

   The first token arrives sooner than it did on Opus, and no pause precedes it
3. Open the AI Insights page: token usage is tagged with the model, so the old and the new cost sit side by side rather than as one unexplained step
4. Put Opus back without touching code - the model is a configuration value, not a class

   ```bash
   Anthropic__Model=claude-opus-4-8 dotnet run --project src/ServiceDeskLite.Api
   ```
5. `dotnet test tests/ServiceDeskLite.Tests.Evaluation` runs the assistant offline against a scripted model; `ThinkingPolicyTests` asserts the request body both call sites actually send

#### What to pay attention to

- The model change is one configuration value and no layer boundary. Domain and Application still compile without an Anthropic reference, which is what makes the decision reversible (ADR 0023)
- Thinking was disabled for the token budget, not for determinism. Sonnet 5 does not accept `temperature` at all; what makes the tool chain predictable is the iteration ceiling and the guard pipeline, and neither changes with thinking (ADR 0035)
- The cost of that choice is named rather than hidden: with thinking off, Sonnet 5 reaches for tools it was not explicitly asked to call somewhat less readily. The countermeasure is prompt-side, and the evaluation suite is the instrument that would see the regression
- The port fix is not a convenience. A container that cannot bind demotes every persistence-dependent test to the in-memory provider, and the tests still pass - against the wrong layer. That is the defect class the manual test plan exists to catch
- The `libgssapi_krb5` line was cosmetic and the fix is not. Removing a cause leaves Kerberos available if the database ever needs it; suppressing the probe from the connection string would have left a reviewer no way to tell a harmless log line from a real one

### Included scope

- Assistant model selection: `claude-sonnet-5` in `AnthropicOptions.Model`, `Thinking = new ThinkingConfigDisabled()` in `AgentLoop` and `TicketSummaryService`, `ThinkingPolicyTests` asserting both - ADR 0038, #185
- `docker-compose.yml` publishes `${DB_PORT:-5432}` and `${API_PORT:-8080}`; container ports and the API connection string are unchanged. New `.env.example`, `.env` gitignored since compose reads `ANTHROPIC_API_KEY` and `VOYAGE_API_KEY` from it - #197, #199
- `Dockerfile`: `libgssapi-krb5-2` in the runtime stage, placed before the publish COPY so the layer caches independently of source changes - #198, #200
- `docs/testing/ai-assistant-manual-test-plan.md`: the full manual pass, its six open findings (#190 through #196), and the untested remainder - #201
- Docs: ADR 0038 and its index entry, runbook section on the port override and its failure message, README refresh - #184

### Known limitations

- Not intended for production use
- The manual pass found six defects this release does not fix. They are recorded, not silently carried: the model confirms ticket changes it never made (#190), `search_knowledge_base` reports technical failures as success (#191), the model has no way to read the agent roster without a failed call (#193), ticket summary timestamps ignore the user timezone (#194), the assistant asks again for a change it was already told to make (#195), and assistant markdown renders as raw text in the web client (#196)
- Sonnet 5 follows instructions more literally than Opus 4.8. Prompt lines written to push a more reluctant model - "always", "if in doubt" - now apply at face value, and the twelve `*.prompt.cs` files are the place to look when a tool fires more often than it should
- Token counts were not re-baselined against `count_tokens` on a real prompt. Sonnet 5 shares the Opus 4.8 tokenizer, so `MaxTokens` and `SummaryMaxTokens` should keep the meaning they were tuned with - that is reasoned, not measured
- Still no real auth, no outbox dispatching, no HTTP-level rate limiting; the owner remains a constant demo identity behind `ICurrentUser`
- The port override is documented for `docker compose` only. The `dotnet run` profiles still bind fixed ports
