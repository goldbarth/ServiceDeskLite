# ServiceDeskLite v1.9.0 - Frontend Redesign: One Visual System, Power-User Speed

### Summary

This release is the M9 milestone: a cohesive overhaul of the web client, from the token scale it is drawn on up to the interactions an operator repeats all day.
Where v1.8.0 hardened what the assistant *does*, this one reworks what the desk *sees and touches* - a single design-token scale, dark mode, richer ticket signals, saved views, a command palette, inline editing, optimistic status moves, and recommended actions that are buttons instead of captions.
The assistant surface joins the same system: answers render as Markdown, and knowledge-base sources are listed under the reply.
Six of the M9 items also close defects found while building it, including three that predated #202 and one recorded back in the v1.7.0 test pass (#196).
The design-token foundation (#202) shipped early under the v1.8.0 tag; it is listed here because it is the base every other M9 change is drawn on, and this is the release where the redesign it enabled is complete.

### Highlights

- **One design-token scale** for spacing, radius, elevation, and semantic color (#202, tagged in v1.8.0). Every surface in this release is drawn on it, and a `DesignTokenTests` guard reads the shipped stylesheets and fails the build on a raw spacing, radius, or color literal where a token applies
- **Dark mode** with a `PaletteDark`, token schemes, and a top-bar toggle (#203). Both themes are first-class, not one tinted from the other
- **Ticket signals carry meaning without relying on color**: status and priority render as chips with an icon, not a color swatch alone (#204); the queue has a fixed row height and a monospaced reference so rows scan as a table, not a list (#205)
- **Saved views**: segmented presets over the ticket list (Unassigned, Overdue, and the rest) that filter without a round-trip through a filter dialog (#206)
- **Command palette on Ctrl/Cmd+K** (#210): opens over any page, navigates from the `NavRegistry` (not a second hard-coded list), and finds tickets through the existing search endpoint, debounced and cancellable - fully keyboard-operable, and it does not swallow the shortcut when a field has focus
- **Actions live where the work is**: status and assignee change through inline popovers instead of modal dialogs, so the ticket stays open and scrolled (#208); a status move on the board or the detail view renders immediately and rolls back to the exact prior state on a rejected transition, with the rejection's `code` in the message (#209); and the first suggested next step is a primary button that runs it through the same command handler as the manual path, with the rest behind an overflow menu (#211, ADR 0041)
- **The assistant reads like a document**: its answers render as sanitized Markdown instead of raw text (#196), knowledge-base sources are listed under the reply (#207, as adapted below), and the internal grounding check no longer appears in the transcript (#189)
- **Redesign defects fixed along the way**: the category column header no longer overlaps Due (#214/#228), the assistant composer's send button sits inside its panel (#215), and long board-card titles clamp to two lines instead of growing the card (#216)

### Demo Notes

#### Suggested demo flow

1. Open the web client and toggle dark mode from the top bar (#203); note that chips, the queue, and the board all recolor from the same token scale rather than inverting

   ```bash
   dotnet run --project src/ServiceDeskLite.Api    # API  → http://localhost:5300
   dotnet run --project src/ServiceDeskLite.Web    # Web  → http://localhost:5310
   ```

2. Press `Ctrl/Cmd+K` anywhere, type a page name or a ticket reference, arrow down, and press Enter; then press it again with a text field focused to confirm the shortcut still opens the palette (#210)
3. Open a ticket: change its status and assignee from the inline popovers without a modal (#208), then run the recommended next step from the primary button (#211). On the board, drag a card to an allowed lane and watch it land before the server answers; drag it to a disallowed lane and watch it roll back with the reason (#209)
4. Ask the assistant a how-to question. The answer renders as Markdown; with a Postgres + Voyage knowledge base configured, the sources it drew on are listed under the reply, and the grounding check runs without appearing in the transcript (#196, #207, #189)

#### What to pay attention to

- The token guard is the mechanism that keeps the redesign coherent: it reads the stylesheets that ship, so a literal that bypasses the scale fails the build rather than drifting in review (#202)
- Optimistic status is reconciled, not assumed: only the newest move reconciles, so two quick changes on one ticket cannot leave the board holding a value the server never accepted (#209)
- The suggested-action mapping is decided server-side, where the reason for each suggestion is known, and the client only renders it - an unmappable suggestion shows as text, never a dead button (#211, ADR 0041)
- Citations are listed as sources under the Markdown answer; anchoring them inline in the rendered Markdown is deferred to #243, because badge injection over plain text and Markdown-to-HTML do not combine trivially

### Known limitations

- Not intended for production use
- Inline citation badges anchored in the answer text are not in this release: the assistant lists sources under the Markdown reply instead, with the inline-anchoring deferred to #243
- The ticket search endpoint matches its query case-sensitively (`q=Remote` finds hits that `q=remote` does not) - shared by the app-bar search, the ticket list, and the command palette; the fix and the broader match-semantics decision are tracked as an ADR issue (#241)
- Several scoped stylesheet rules were found to target MudBlazor component roots, where Blazor CSS isolation does not stamp the scope attribute, so the rule silently does nothing; one visible case was fixed (#215) and an audit plus a guard test is tracked (#242)
- Still no real auth, no outbox dispatching, no HTTP-level rate limiting; the owner remains a constant demo identity behind `ICurrentUser`
- The conversation resume UI is still not built: transcript state is persisted server-side, but the web client does not yet reload a prior conversation
