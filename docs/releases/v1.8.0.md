# ServiceDeskLite v1.8.0 - Assistant Hardening: Grounding as a Mechanism, Honest Writes

### Summary

v1.7.0 ended with a recorded manual test pass and six open defects.
This release is what working through that list produced, plus the deeper question the list pointed at: which of the assistant's safety properties actually hold, and which are just sentences in a prompt the model may or may not follow.
Five of the six recorded defects are fixed; the sixth (#196, markdown rendering) is a web concern and moves with the frontend redesign.
The structural change is bigger than any single fix: the grounding check is now enforced by the loop instead of requested by the prompt, and it scores meaning instead of counting words - a correct paraphrase or a German answer against an English knowledge base no longer fails its own verification.
Around the writes, one policy now governs both failure directions the field pass caught: never claim a change without a successful tool result, and never re-ask for a change the user already ordered.
Everything landed as its own milestone (M10 - Assistant Hardening), kept deliberately separate from the frontend redesign, which now collects on its own integration branch.

### Highlights

- **The grounding check is a mechanism, not a request** (ADR 0039, #187). Once knowledge-base passages have been retrieved and no check has run, the loop forces `check_grounding` via `tool_choice`: the model writes its draft as the tool argument, and the verdict is computed before the first token streams. A model that self-checks is never forced; the constraint is the backstop for the turn it would have skipped. It holds for the chat and the autonomous worker alike, because they share one loop
- **Grounding scores meaning, not word overlap** (ADR 0040, #188). Each substantive answer sentence is embedded with the retrieved passages in one Voyage call and judged by cosine similarity to its nearest passage. The lexical evaluator failed a correct paraphrase, a correct translation, and the exact hedge the prompt demands - all scored ~0.00. It survives as the fallback when embeddings are unavailable, so the enforced check always returns a verdict
- **Write honesty and confirmation policy** (#190, #195). The system prompt now states both rules the field pass found missing: never state a change happened unless the tool call succeeded in this conversation, and when the user already asked for a change, make it - no re-asking, not even after correcting an earlier mistake. The two defects are opposite ends of one trade-off, which is why they share one policy and shipped as one change
- **Every tool description says when to call it** (#186). Five of twelve described only mechanics; all twelve now carry a call-timing clause, and a deterministic guard test over `ToolDispatcher.Definitions` fails the build if a future tool ships without one. The `update_ticket` clause closes with "actually apply the change; do not just confirm it in prose" - aimed squarely at the recorded failure
- **The agent roster reaches the model before it guesses** (#193). The chat system prompt names the active agents per request, from the same query `assign_ticket` validates against. Previously the roster entered the transcript only inside a failed call's error message, where the model paraphrased "Morgan Diaz" into a "Morgan Davis" that does not exist
- **A failed knowledge-base search is an error** (#191). A broken Postgres query or Voyage failure returned `IsError: false` and was indistinguishable from a clean search - for the model, the dashboard's error rate, and the retry policy. Now it reads as a failure, distinct from the honest "unavailable" degradation
- **Summary timestamps respect the user timezone** (#194). A comment written at 12:07 local appeared in the summary as 10:07: the summary prompt fed the model UTC while the UI rendered local times next to it. The ticket prompt now converts every timestamp to `Anthropic:UserTimeZone` and names the zone

### Demo Notes

#### Suggested demo flow

1. Run the API with a real model and ask a how-to question that hits the knowledge base

   ```bash
   dotnet run --project src/ServiceDeskLite.Api
   ```

   Watch the SSE stream: after `search_knowledge_base`, a `check_grounding` call appears before the answer text - forced by the loop if the model did not check on its own
2. Replay the recorded #190 case: create a ticket in one turn, then send "Setze die Priorität auf Critical". The `update_ticket` call fires before any confirmation text, and the confirmation cites the actual result
3. Ask it to assign a ticket to an agent by name. The valid names are in the prompt now - the model lists real agents instead of paraphrasing an error message from a failed attempt
4. `dotnet test tests/ServiceDeskLite.Tests.Evaluation` shows the deterministic side: `GroundingEnforcementTests` reads the `tool_choice` the loop sends upstream, `RosterInPromptTests` reads the system prompt the model actually received, `ToolDescriptionGuidanceTests` fails the build on a description without a call-timing cue

#### What to pay attention to

- The enforcement pattern: a safety property phrased as a prompt request depends on model behaviour, and model behaviour changes per release. ADR 0037's standard - "a rule the model can talk itself out of is not a rule" - now also holds for the one property that was still a request
- The grounding verdict is deliberately not surfaced to users or the dashboard. With the semantic detector the old objection (false alarms on correct answers) is resolved, but whether a score helps a user at all is a product question the citations already mostly answer - it stays internal until that question has an answer
- The #190/#195 pair could not be pinned by the scripted evaluation suite - it would assert its own script (ADR 0037). Verification was a live pass against the real model, replaying the recorded field cases before and after the prompt change; the write-honesty rules are the regression lock, in prose
- What the enforced grounding check costs: one extra model turn, only when the model did not self-check. The prompt still steers toward self-checking, so the forced turn is the exception path

### Included scope

- Grounding enforcement: `tool_choice` narrows to `check_grounding` when passages exist and no check ran; force-once per run - ADR 0039, #187, PR #218
- Semantic grounding: `IGroundingEvaluator` port, `SemanticGroundingEvaluator` (one embedding call, per-sentence cosine), `LexicalGroundingEvaluator` as fallback - ADR 0040, #188, PR #219
- Tool-description call-timing clauses on `update_ticket`, `assign_ticket`, `change_ticket_status`, `add_comment`, `remember`, plus the build-time guard - #186, PR #217
- Write-honesty and confirmation policy in the chat system prompt - #190, #195, PR #223
- Agent roster injected into the chat system prompt from `GetAgentsHandler`; ADR 0025 notes `list_agents` as the path if the roster outgrows a prompt line - #193, PR #221
- `search_knowledge_base` catch branch returns `IsError: true`, distinct from "unavailable"; transient faults still rethrow to the retry policy - #191, PR #220
- Summary timestamps converted to `Anthropic:UserTimeZone` in `BuildTicketPrompt`, zone named in the prompt header - #194, PR #222
- Web design tokens (#202, PR #213) are also part of this tag: the M9 frontend-redesign foundation landed on main before the strands were separated; all remaining M9 work collects on the `m9-frontend-redesign` integration branch and ships as its own release
- ADRs 0039 and 0040; ADR 0025 and 0031 amended; README and runbook updated

### Known limitations

- Not intended for production use
- Assistant markdown still renders as raw text in the web client (#196) - a web concern, scheduled with the M9 frontend redesign, where the fix must sanitize before `MarkupString` because ticket content is user-controlled
- The grounding score chip in the web UI contradicts the prompt's "never mention the score" instruction (#189); the resolution is part of the M9 assistant-presentation work
- The semantic grounding path is not deterministic: two runs of the same answer can differ if the embeddings differ. The verdict bands, the fallback, and fixture tests with a fake embedder keep the logic pinned; exact reproducibility now belongs only to the lexical path
- The live measurement #186 originally asked for - how often each tool fires when it should, counted against the audit log over a real scenario set - remains unbuilt. The cheap mitigation shipped first on purpose: any future measurement now runs against the improved descriptions, so a residual skip is signal rather than noise
- Grounding still scores every substantive sentence, including greetings and confirmations that are not claims about the sources. It does not bite while `check_grounding` receives only the model's draft; it would bite if anything graded a finished answer
- Still no real auth, no outbox dispatching, no HTTP-level rate limiting; the owner remains a constant demo identity behind `ICurrentUser`
