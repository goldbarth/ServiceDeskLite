# ServiceDeskLite v1.3.0 — Knowledge-Base RAG, Hybrid Retrieval & Grounding

### Summary

ServiceDeskLite 1.3.0 grows the optional, ticket-only semantic search from 1.2.0
into a full knowledge system (roadmap milestone M5). The assistant now answers
how-to and policy questions from a dedicated knowledge-base corpus and streams the
source citations it drew on. Ticket retrieval becomes hybrid — semantic and keyword
signals fused into one ranked, metadata-filtered result instead of either alone. And
every knowledge-base answer is checked for grounding against its sources, so the
agent hedges or re-retrieves rather than asserting an unsupported claim. Everything
stays optional and degrades honestly: without a Voyage key or on the InMemory
provider, the app reports search/citations/grounding as unavailable instead of
faking them.

### Highlights

- Knowledge-base RAG: a `/KnowledgeBase` corpus (articles, FAQ, internal docs), chunked on headings and embedded by a background worker, with answers that stream cited sources over SSE (ADR 0029)
- Hybrid ticket retrieval: `find_similar_tickets` fuses semantic (pgvector) and keyword signals with Reciprocal Rank Fusion, adds optional status/priority filters, and returns a per-result relevance score plus the signals that matched (ADR 0030)
- RAG grounding evaluation: a deterministic `check_grounding` tool scores a drafted answer against the passages actually retrieved; weak grounding makes the agent re-retrieve, drop the claim, or hedge (ADR 0031)
- New assistant tools `search_knowledge_base` and `check_grounding` (ten tools total)
- Web: retrieved sources render as a "Sources" card; answers carry a grounding badge
- Build: versions are now derived from git tags via MinVer — a release is a tag, no hardcoded version

### Demo Notes

#### Suggested demo flow

1. Start the app with `ANTHROPIC_API_KEY`, plus `Voyage:ApiKey` and PostgreSQL for the full RAG path
2. Ask a how-to question ("how do I reset a locked account?") — the assistant searches the knowledge base and answers with cited sources
3. Watch the streamed answer, the "Sources" card, and the grounding badge
4. Describe a problem and let it run a duplicate check — `find_similar_tickets` returns hybrid-ranked matches with a relevance score and the matched signals
5. Narrow a dedup check by status or priority to see the metadata filters constrain results
6. Run the same flows on InMemory (or without a Voyage key) and watch every RAG feature degrade honestly instead of inventing sources

#### What to pay attention to

- Knowledge-base answers cite only passages that were actually retrieved; when search is unavailable the assistant says so and cites nothing
- The grounding check is deterministic and runs against the real retrieved passages, not the model's memory
- Hybrid fusion is provider-agnostic — it degrades to labelled keyword-only when the semantic signal is unavailable
- All retrieval and writes still flow through the same application-layer handlers and the edge-adapter stance from earlier releases

### Included scope

- Knowledge-base corpus loading, heading chunking, embedding worker, pgvector search, and streamed citations (API + web) — #156
- Hybrid ticket retrieval: RRF fusion of semantic + keyword, metadata (status/priority) filters, per-result relevance — #157
- Deterministic grounding evaluator, `check_grounding` self-check tool, per-request retrieval context, grounding badge — #158
- Build/versioning: MinVer derives the version from git tags (`v`-prefixed) — #172

### Known limitations

- Not intended for production use
- Still no real auth — the roster is seeded fictitious accounts, not authenticated identities
- Knowledge-base RAG, streamed citations, and grounding-against-real-sources require PostgreSQL + a Voyage API key; without them these features report unavailable and the rest of the app is unaffected
- The grounding check is lexical, so it assumes an answer and its sources share a language; cross-lingual grounding is deferred
- Hybrid retrieval keeps substring keyword matching (no full-text index) and hand-tuned fusion weights; chunking, re-ranking, and learned ranking remain out of scope
